# 三需求实施计划（按你的澄清修订：不建拆分 Agent，主 Agent 拆分 + 代码层强制容器）

## 需求 2（核心）：任务容器 + 代码层强制

主 Agent 仍负责拆分（LLM），但「写入容器」必须是代码强制的工具调用，而非自由 write_file：

**新增任务容器（双容器）**
- `service/TaskRegistry.java`：内存容器 `ConcurrentHashMap<"userId:sessionId", SessionTaskContainer>`；`SessionTaskContainer` 持有任务记录列表（taskId/描述/建议工具/优先级/状态 PENDING→IN_PROGRESS→DONE/FAILED）与 MD 文件路径
- `agent/tools/TaskTools.java`（@Tool 注册进 Toolkit，主/子 Agent 都可调用）：
  - `create_task_backlog(sessionId, tasksJson)`：**唯一合法的清单入口**——解析 JSON 任务数组 → 写 MD 到隔离路径 → 登记内存容器 → 返回「清单已登记，共 N 项」
  - `get_task_progress(sessionId)`：主 Agent 查询「共 N 项：已完成 x / 进行中 y / 待处理 z，未完成：T2、T3…」
  - `update_task_status(sessionId, taskId, status)`：子 Agent 执行时逐项更新（已验证子代理可调 Toolkit 工具）

**委派门禁（代码强制，不靠提示词自觉）**
- `agent/PlanningGateMiddleware.java` 实现 `MiddlewareBase.onActing`（本会话已验证 ActingInput 是 public Record、ToolUseBlock 构造器 public）：
  当 intent=PLANNING 且出现 `agent_spawn` 调用、但 TaskRegistry 中该会话无任务时 → **重写 ActingInput**：把 agent_spawn 替换为真实工具 `planning_gate_hint`（返回纠正指令「先调 create_task_backlog 再委派」），agent_spawn 根本不执行，ReAct 循环看到纠正结果后自我修正
- `IntentRouterMiddleware` 的 PLANNING 指令升级：注入本轮会话的具体协作路径（`tasks/{sessionId}/task_backlog.md` 等）与工具调用顺序说明

**隔离设计（需求 1）**
- 用户级：harness 已按 RuntimeContext.userId 自动隔离（实测文件落在 `workspace/2/`），主 Agent 与 SHARED 子代理同根，保持
- 会话级（本次新增）：协作文件全部收敛到相对路径 `tasks/{sessionId}/` 下；`TaskWorkspaceService` 路径改为 `{workspaceRoot}/{userId}/tasks/{sessionId}/`（当前缺用户级），并提供相对路径 helper
- `TaskRegistry` 按 `userId:sessionId` 键隔离；验证方式：两个会话各规划一次，磁盘上出现两个独立任务目录，互不干扰
